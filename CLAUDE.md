# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Summary

DigiPoz is a Serbian wedding invitation platform with 29 unique designs (10 original 2025 themes + 19 standalone 2026 layouts). Couples fill an intake form (`public/form.html`), which triggers automated preview generation, theme selection, final site publishing, and guest RSVP tracking — all via Google Apps Script webhooks, GitHub Actions, and GitHub Pages.

**Domain:** pozivnice.rs | **Language:** Serbian Cyrillic | **Hosting:** GitHub Pages

## Commands

```bash
npm run serve                # Dev server on port 3000, serves public/
npm run preview              # node scripts/generate-preview.js <slug>
npm run generate             # node scripts/generate-final.js <slug> <theme>
npm run layout               # node scripts/generate-layout-preview.js <layout> [slug]
npm run layout:all           # Generate all 19 layout previews
npm run layout:list          # List available 2026 layouts
npm run cleanup              # Remove expired previews (>24h)
npm run validate             # Validate config.js settings
npm run screenshots          # Generate theme screenshots (requires Playwright)
```

No test suite or linter is configured.

## Architecture

See `docs/architecture.md` for the complete technical reference.

### Two Template Systems

**Original (2025):** Single `templates/base.html` shared by 10 themes. Themes differ only in CSS (`templates/themes/{theme}/style.css`). Generated by `generate-preview.js` and `generate-final.js`.

**2026 Layouts:** Standalone `templates/base-{layout}.html` files (19 layouts: aurora, botanical, cinema, concert, envelope, filmnoir, gazette, glass, kinetic, letter, magazine, mediterranean, oldmoney, passport, scribble, storybook, telegram, velvet, wabisabi) with completely different HTML structures. Each layout has themes in `templates/themes-{layout}/{theme}/`. Generated by `generate-layout-preview.js` (previews) and `generate-final.js` (final sites).

### CSS Assembly

For the original system, `generate-final.js` concatenates CSS into two build-time replacements:

- `{{THEME_CSS}}` = `themes/{theme}/style.css` only
- `{{ANIMATIONS_CSS}}` = `animations.css` + `components.css` + `backgrounds.css` + `decorations.css` + `mobile.css`

Additional shared CSS files exist (`tokens.css`, `shared-forms.css`, `shared-sections.css`) but are not part of the `{{ANIMATIONS_CSS}}` bundle.

2026 standalone templates have their own inline `<style>` blocks. Their `{{THEME_CSS}}` is assembled from `tokens.css` + `mobile.css` + `themes-{layout}/{theme}/style.css`.

### Template Variable System

Implemented in `scripts/utils.js` (original) and `scripts/generate-layout-preview.js` (2026):

- `{{VARIABLE}}` — HTML-escaped replacement. Fields ending in `_URL` or `_ISO` are not escaped.
- `{{#IF_CONDITION}}...{{/IF_CONDITION}}` — Conditional blocks. Shown when the matching data key is truthy.
- Raw HTML fields (no escaping): `THEME_CSS`, `ANIMATIONS_CSS`, `THEME_FONTS`, `CALENDAR_BUTTONS`, `TIMELINE_ITEMS`, `GALLERY_ITEMS`, `MEAL_OPTIONS`, `MEAL_OPTIONS_HTML`, `DRESS_CODE_COLOR_SWATCHES`, `_themeCss`, `_themeFonts`, `STORY_CARDS`.

### Generation Pipeline

```
Original (2025):
data/{slug}.json → generate-preview.js → public/preview/{slug}/ (10 themed HTMLs + index.html)
                 → generate-final.js    → public/site/{slug}/    (single themed index.html)

2026 Layouts:
data/{slug}.json → generate-layout-preview.js → public/preview/{slug}-{layout}/ (themed HTMLs + index.html)
                 → generate-final.js           → public/site/{slug}/             (single themed index.html)
```

For final generation, `generate-final.js` supports both systems:
- Original themes: `node scripts/generate-final.js ana-marko classic`
- 2026 layouts: `node scripts/generate-final.js ana-marko envelope/velvet`

### Automation Flow

Google Apps Scripts in `google-apps-script/` bridge external services to GitHub:

1. `intake-form-handler-automated.gs` — Google Form submit → creates per-couple RSVP spreadsheet → triggers `repository_dispatch` → `generate-preview.yml`
2. `theme-selection-handler-automated.gs` — Theme selection POST → triggers `repository_dispatch` → `generate-final.yml`
3. `rsvp-handler.gs` — Guest RSVP POST → looks up per-couple spreadsheet via `RSVP_Lookup` tab → writes to dedicated per-couple Google Spreadsheet

Legacy (non-automated) versions also exist: `intake-form-handler.gs`, `theme-selection-handler.gs`.

### RSVP System

All invitations share one global `RSVP_SCRIPT_URL`. The `slug` in the POST body routes to the correct per-couple spreadsheet. All templates use `mode: 'no-cors'` with `Content-Type: text/plain;charset=utf-8` to avoid CORS preflight failures with Google Apps Script.

### Key Modules

- `scripts/config.js` — Theme/layout registry (`LAYOUT_REGISTRY` with `isOriginal` flag), Google Script URLs, domain config
- `scripts/utils.js` — Template processing (`replacePlaceholders`, `processConditionals`), Cyrillic-to-Latin `slugify`, date formatting, calendar link generation, data validation
- `scripts/generate-layout-preview.js` — Unified generator for all 19 2026 layouts. Has its own `replacePlaceholders` and `processConditionals` (not shared with utils.js)
- `templates/script.js` — Client-side JS inlined into original invitations (countdown, gallery lightbox, RSVP form, scroll animations, confetti)

### Security

- **Workflow inputs:** Validated with regex and passed via `env:` blocks (never `${{ }}` in shell)
- **Template XSS:** Variables HTML-escaped by default; raw fields explicitly whitelisted
- **RSVP CORS:** All templates use `no-cors` + `text/plain` for GAS compatibility
- **Privacy:** `noindex, nofollow` on all invitation templates

## Conventions

- All user-facing text is in **Serbian Cyrillic**. Date formatting uses Serbian genitive month names ("јануара", "фебруара").
- Wedding data JSON uses snake_case keys (`bride_name`, `ceremony_venue`, `wedding_date`).
- Template placeholders use SCREAMING_SNAKE_CASE (`{{BRIDE_NAME}}`).
- Slugs are auto-generated from Cyrillic names via transliteration (`Ана-Марко` → `ana-marko`).
- The client-side `script.js` uses an IIFE with `'use strict'` and checks for demo mode by detecting unreplaced `{{RSVP_SCRIPT_URL}}` in the config.
- Output is fully self-contained single-file HTML (all CSS and JS inlined, no external dependencies except Google Fonts).

## Known Issues

- `generate-layout-preview.js` duplicates `formatDate`, `processConditionals`, `replacePlaceholders` from `utils.js` — these should be consolidated.
- Calendar links (`{{CALENDAR_BUTTONS}}`) only rendered in `base.html` and `base-envelope.html`; placeholder support exists in the layout generator but HTML not yet added to other 2026 templates.
- No automated tests or linting.
